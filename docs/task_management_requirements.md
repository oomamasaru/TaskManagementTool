# タスク管理ツール 要件定義書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 文書名 | タスク管理ツール 要件定義書 |
| 対象 | デスクトップ向けローカル完結型タスク管理ツール |
| 実装言語 | Python 3.12 |
| GUI | PyQt6 |
| データ保存 | JSON ファイル |
| 作成方針 | シンプルな UI を維持しつつ、日常利用に十分な機能を備える |

---

## 2. 目的

本ツールは、ローカル環境で軽快に動作するシンプルなタスク管理ツールを実現することを目的とする。

主な目的は以下のとおりとする。

- カテゴリごとにタスクを整理し、視覚的に把握しやすくする。
- タスクの優先順をドラッグ操作で直感的に変更できるようにする。
- タスク名、期限、ラベル、ステータス、詳細などの情報をまとめて管理できるようにする。
- テキスト検索およびラベルフィルタにより、必要なタスクをすばやく探せるようにする。
- 自動保存およびバックアップにより、データ消失リスクを低減する。
- Undo / Redo により、誤操作から復旧しやすくする。

---

## 3. スコープ

### 3.1 本要件で対象とする範囲

- タスクの作成、編集、削除、複製
- カテゴリ管理
- ラベル管理
- ステータス管理
- タスクの並び替え
- 検索 / フィルタ
- 完了済みタスク管理
- JSON 保存 / bak バックアップ
- Undo / Redo

### 3.2 本要件で対象外とする範囲

以下は将来対応とし、本要件には含めない。

- 繰り返しタスク
- DB 利用
- クラウド同期
- 複数ユーザー対応
- 権限管理
- 通知機能
- カレンダー連携

## 4. 用語定義

| 用語 | 定義 |
|---|---|
| カテゴリ | 画面上の列。タスクが所属する単位。1 タスクは 1 カテゴリにのみ所属する。 |
| ラベル | タスクの属性。複数付与可能。例: A案件、Bツール、保守、調査。 |
| 優先順 | 同一カテゴリ内でのタスクの表示順。上にあるほど優先度が高い。 |
| ステータス | タスクの進捗状態。未着手、作業中、完了など。 |
| 完了済みタスク | ステータスが完了となり、通常のメイン一覧には表示されないタスク。 |
| Undo | 直前の操作を取り消す機能。 |
| Redo | Undo により取り消した操作を再適用する機能。 |

## 5. システム概要

### 5.1 全体方針

本ツールは、ローカル完結型のデスクトップアプリケーションとする。
データは DB ではなく JSON ファイルで管理し、ユーザーが扱いやすく、バックアップしやすい構成とする。

UI は極力シンプルにし、メイン画面では以下を重視する。

- 一覧性
- 直感的な操作
- 視認性
- 誤操作防止

### 5.2 画面構成の基本方針

- 画面中央にカテゴリ列を横並びで表示する。
- 各カテゴリ列の中にタスクカードを縦に表示する。
- タスクカードはドラッグアンドドロップで並び替え可能とする。
- タスクカードクリックで詳細ダイアログを表示する。
- 完了済みタスク、ラベル管理、ステータス管理などはメイン画面を汚さないようにダイアログまたは設定画面で扱う。

## 6. 機能要件

## 6.1 メイン画面

### 6.1.1 カテゴリ表示

- カテゴリを画面上で横並びの列として表示する。
- 例として、カテゴリが 3 件存在する場合は、左から順に A、B、C の列として表示する。
- 各カテゴリ列にはカテゴリ名を表示する。
- 各カテゴリ列の上部にタスク追加ボタンを配置する。

### 6.1.2 タスクカード表示

各タスクはカード形式で表示する。

カードには以下の情報を表示する。

| 項目 | 表示要否 | 備考 |
|---|---|---|
| タスク名 | 必須 | カード上に表示 |
| 期限 | 必須 | カード上に表示 |
| ラベル | 必須 | カード上に表示 |
| 残り日数 | 必須 | カード右上に控えめに表示 |
| ステータス色 | 必須 | カード左端の帯色で表現 |
| タスク色 | 必須 | カード背景色に反映 |

### 6.1.3 色表現

色の役割は以下のように分離する。

| 対象 | 色の役割 | 色の傾向 |
|---|---|---|
| タスク / ラベル | 属性・視認性の補助 | 比較的薄めの色 |
| ステータス | 進捗状態の識別 | 比較的濃い色 |
| 期限警告 | 緊急度の識別 | 残り日数表示部の色で表現 |

期限警告はカード右上の残り日数表示の文字色または背景色で表現する。

### 6.1.4 タスク並び替え

- 同一カテゴリ内のタスクはドラッグアンドドロップで並び替え可能とする。
- 優先順はカテゴリごとに独立して管理する。
- 並び替え結果は自動保存対象とする。

---

## 6.2 タスク管理

### 6.2.1 タスク追加

- 各カテゴリ列上部のタスク追加ボタン押下により、タスク詳細ダイアログを表示する。
- タスク追加時は対象カテゴリを初期値として設定する。
- タスク作成時の初期ステータスは必ず `未着手` とする。

### 6.2.2 タスク編集

- タスクカードクリックでタスク詳細ダイアログを表示する。
- タスク詳細ダイアログ上で各項目を編集できるようにする。
- 編集確定時は自動保存対象とする。

### 6.2.3 タスク削除

以下の 2 つの導線を用意する。

- タスクカード右クリックメニューから削除
- タスク詳細ダイアログから削除

削除時は確認ダイアログを表示する。

### 6.2.4 タスク複製

- タスク詳細ダイアログに複製ボタンを配置する。
- 複製時は元タスクの内容を引き継いだ新規タスクを作成する。
- 複製タスクのステータス初期値は元タスクを引き継ぐ。
- 複製タスクの作成日時 / 更新日時は新規作成時刻で再設定する。
- 完了日時は複製しない。

### 6.2.5 タスク詳細項目

タスクに設定可能な情報は以下とする。

| 項目 | 必須 | 備考 |
|---|---:|---|
| タスク ID | ○ | システム内部用、一意識別子 |
| タスク名 | ○ | カード表示対象 |
| 期限 |  | カード表示対象 |
| ラベル |  | 複数選択可能、カード表示対象 |
| タスク色 |  | カード背景色 |
| タスク詳細 |  | 詳細ダイアログに表示 |
| カテゴリ | ○ | 1 タスク 1 カテゴリ所属 |
| ステータス | ○ | 未着手 / 完了は必須 |
| 完了日時 |  | 完了時に自動設定 |
| 作成日時 | ○ | 自動設定 |
| 更新日時 | ○ | 自動設定 |
| 並び順 | ○ | カテゴリ内順序 |

---

## 6.3 ステータス管理

### 6.3.1 ステータスの基本方針

ステータスは、固定ステータスとカスタムステータスに分けて管理する。

### 6.3.2 固定ステータス

以下のステータスは必須の固定ステータスとする。

| 内部 ID | 表示名 | 削除可否 | 備考 |
|---|---|---:|---|
| `not_started` | 未着手 | 不可 | タスク新規作成時の初期値 |
| `completed` | 完了 | 不可 | メイン一覧から非表示対象 |

### 6.3.3 初期搭載ステータス

以下のステータスを初期状態で定義する。

| 内部 ID | 表示名 | 削除可否 |
|---|---|---:|
| `in_progress` | 作業中 | 可 |

### 6.3.4 カスタムステータス

- ユーザーは設定ダイアログからカスタムステータスを追加・編集・削除できる。
- ステータスには表示順と色を設定できる。
- ステータス色はカード左端の帯色に反映する。

### 6.3.5 完了時の挙動

- ステータスを `完了` に変更した場合、完了日時を自動設定する。
- 完了タスクは通常のメイン一覧から非表示とする。
- 完了タスクは完了済みタスク一覧ダイアログで参照できるようにする。

### 6.3.6 完了タスク復活時の挙動

- 完了済みタスク一覧からタスクを復活できるようにする。
- 復活時はステータスを `未着手` に戻す。
- 復活時は完了日時を `null` にする。

### 6.3.7 ステータス削除時のルール

- 固定ステータスは削除不可とする。
- カスタムステータスを削除する際、当該ステータスを使用中のタスクが存在する場合は置換先ステータスの選択を必須とする。

---

## 6.4 完了済みタスク管理

### 6.4.1 完了済みタスク一覧

- 完了済みタスクは別ダイアログで表示する。
- メイン画面には表示しない。

### 6.4.2 表示項目

完了済みタスク一覧では、少なくとも以下の情報を表示する。

- タスク名
- 元カテゴリ
- ラベル
- 期限
- 完了日時
- 詳細プレビュー

### 6.4.3 操作

完了済みタスク一覧では以下の操作を可能とする。

- 詳細表示
- 復活
- 完全削除
- 検索

### 6.4.4 並び順

- 完了済みタスク一覧では、完了日時の降順で表示する。

---

## 6.5 カテゴリ管理

### 6.5.1 カテゴリ追加

- カテゴリ追加はメニューから実行できるようにする。
- 常時メイン画面上にはカテゴリ追加 UI を表示しない。

### 6.5.2 カテゴリ削除

- カテゴリ削除はメニューまたは管理ダイアログから実行できるようにする。
- カテゴリ削除時の選択肢は以下の 2 つのみとする。
  - タスクも一緒に削除
  - 削除中止
- 削除確認時は、配下タスク件数を明示した強めの警告メッセージを表示する。

例:

- 「カテゴリ A を削除すると、その中のタスク 12 件も削除されます。」

### 6.5.3 カテゴリ削除の Undo 対応

- カテゴリ削除に対する Undo は将来対応とし、本要件には含めない。

---

## 6.6 ラベル管理

### 6.6.1 ラベル管理 UI

- ラベル管理はダイアログで行う。
- メイン画面とは分離し、必要時のみ表示する。

### 6.6.2 ラベル設定項目

ラベルに設定可能な項目は以下とする。

| 項目 | 必須 | 備考 |
|---|---:|---|
| ラベル ID | ○ | システム内部用 |
| ラベル名 | ○ | 表示名 |
| ラベル色 | ○ | タスク色と同系統で使用 |
| 表示順 | ○ | ラベル一覧表示順 |

### 6.6.3 ラベル削除時のルール

- ラベル削除時は、使用中タスクから当該ラベルを取り外す。
- タスク自体は削除しない。

---

## 6.7 フィルタ / 検索

### 6.7.1 テキスト検索

- 画面右上にテキスト入力欄を設ける。
- タスク名およびタスク詳細を対象とした部分一致検索を行う。
- 入力内容は同期的に一覧へ反映する。
- 大文字小文字は区別しない。

### 6.7.2 ラベルフィルタ

- ラベルフィルタはボタン型 UI で表示する。
- チェックボックス形式は採用しない。
- ラベルごとに ON / OFF を切り替えられるようにする。
- ON のラベルは本来のラベル色で表示する。
- OFF のラベルは同系統の暗い色で表示する。
- OFF 状態でもボタンとして押下可能であることが分かる視覚表現を残す。
- `ラベル設定なし` の選択肢も用意する。

### 6.7.3 フィルタ条件

- 複数ラベル選択時は OR 条件とする。
- テキスト検索とラベルフィルタは AND 条件とする。

### 6.7.4 フィルタクリア

- テキスト検索条件およびラベルフィルタ条件を一括で解除するフィルタクリアボタンを設ける。

---

## 6.8 期限表示

### 6.8.1 表示方式

- 期限までの残り日数をカード右上に控えめに表示する。

### 6.8.2 色分け

残り日数表示に対して、期限状態に応じた色分けを行う。

例:

| 状態 | 表現例 |
|---|---|
| 期限切れ | 赤系 |
| 今日まで | 黄または橙系 |
| 未来 | 通常色 |
| 期限なし | 弱い表示または非強調 |

具体的なしきい値や配色は詳細設計で定める。

---

## 6.9 自動保存 / バックアップ

### 6.9.1 保存方式

- データは単一 JSON ファイルに保存する。
- ユーザー操作ごとに自動保存する。

### 6.9.2 バックアップ方式

- JSON 保存時、保存前のファイルを `.bak` として退避する。
- `.bak` は障害復旧および JSON 破損時の復元用とする。

### 6.9.3 バックアップの位置づけ

- `.bak` は Undo / Redo の主機能としては扱わない。
- Undo / Redo はアプリケーション内の操作履歴で管理する。

---

## 6.10 Undo / Redo

### 6.10.1 実現方式

- Undo / Redo はコマンド方式で実装する。
- 各操作をコマンドとして履歴スタックに積む。

### 6.10.2 対象操作

本要件で Undo / Redo 対象とする操作は以下とする。

- タスク追加
- タスク削除
- タスク編集
- タスク移動 / 並び替え
- ステータス変更
- タスク複製

### 6.10.3 対象外操作

以下は本要件では Undo / Redo 対象外とする。

- カテゴリ削除
- 大きな設定変更全般の一部

### 6.10.4 UI 導線

- メニューに Undo / Redo を配置する。
- ショートカットキーを割り当てる。
  - Undo: `Ctrl + Z`
  - Redo: `Ctrl + Y` または `Ctrl + Shift + Z`

## 9. 業務ルール / 決め打ちルール

| 項目 | ルール |
|---|---|
| 新規タスクの初期ステータス | 未着手 |
| 完了タスクのメイン画面表示 | 非表示 |
| 完了タスクの復活時ステータス | 未着手 |
| 完了タスクの復活時 completed_at | null にする |
| 完了済み一覧の並び順 | 完了日時降順 |
| 完了タスクの編集 | 可能 |
| ラベル削除時 | 使用中タスクからラベルを外す |
| ステータス削除時 | 使用中タスクがあれば置換先選択必須 |
| カテゴリ削除時 | 配下タスクも削除するか、中止するかの 2 択 |
| 期限未設定 | 期限警告の対象外 |
| 詳細未入力 | 空文字で保持 |

## 10. 非機能要件

## 10.1 操作性

- 一般的なデスクトップアプリとして違和感のない応答速度を維持する。
- タスク並び替え、検索、フィルタ反映はストレスなく行えること。

## 10.2 保守性

- データ構造は拡張しやすい JSON 構造とする。
- ステータス、ラベル、カテゴリは独立した管理単位として設計する。
- Undo / Redo はコマンド単位で実装し、今後の操作追加に対応しやすくする。

## 10.3 信頼性

- 各操作後に自動保存を行う。
- 保存前には bak を作成し、障害復旧しやすくする。
- 誤削除につながる操作には確認ダイアログを設ける。

## 10.4 UI 品質

- 画面は極力シンプルにする。
- 常時使わない操作はメニューまたはダイアログへ寄せる。
- 色の役割を明確に分け、情報の意味が競合しないようにする。

## 11. 実装上の補足方針

### 11.1 自動保存の難易度

本ツールの規模であれば、各操作ごとの JSON 自動保存は高難易度ではない。
ただし、以下の点は考慮する。

- 保存中の例外処理
- 書き込み失敗時のユーザー通知
- 保存途中でのファイル破損防止
- bak 作成との整合性

### 11.2 Undo / Redo と保存の関係

- 通常操作実行後は自動保存する。
- Undo 実行後も自動保存対象とする。
- Redo 実行後も自動保存対象とする。
- これにより、アプリ終了時点の状態と保存データを一致させる。

## 13. まとめ

本ツールは、カテゴリ・ラベル・ステータスの役割を明確に分離し、
ローカル完結・シンプル UI・高い操作性を両立するタスク管理ツールとして実装する。

特に以下を本要件の核とする。

- カテゴリ別の視覚的管理
- ドラッグによる優先順変更
- ステータス管理と完了済みタスク分離
- テキスト検索とラベルフィルタ
- JSON + 自動保存 + bak による安全なデータ管理
- コマンド方式 Undo / Redo

以上を本要件定義の確定仕様とする。
